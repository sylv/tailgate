# Writing

Write like a person explaining something to a coworker. Short, plain and specific

- No em dashes, en dashes, hyphens used as dashes or semicolons. Use a period or a comma
- No period at the end of a list item, paragraph or section. Periods only split sentences
- No bold, including bold labels like `**Auth:**`
- A colon goes before a list or an example, never mid-sentence as a connector
- Use the plain word. "use", not "utilize" or "leverage". "is" or "has", not "serves as" or "boasts"
- No AI vocabulary: additionally, crucial, delve, enhance, foster, landscape, pivotal, robust, seamless, showcase, underscore
- No abstract metaphor nouns like surface, primitive, scaffolding or paradigm. Use the concrete word
- No trailing "-ing" phrases that add no fact ("ensuring...", "highlighting...")
- No "not just X, but Y". State the point
- Don't force ideas into threes
- One name per thing. Repeat it instead of switching synonyms
- Cut filler. "in order to" becomes "to". Delete "it's important to note that"
- One hedge at most
- Say what it does, not how it feels. Name the mechanism or the number. Cut any sentence that could appear unchanged in another project's docs
- One idea per sentence, in active voice. Cut adverbs or use a stronger verb
- No generic conclusions, emojis, praise or chatbot phrases
- Sentence case headings and straight quotes

Commit messages are short and lowercase, like `fix funnel cert retry`. Code comments are lowercase and casual, and only explain what the code can't
